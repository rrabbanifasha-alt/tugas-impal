# 3. DESKRIPSI RINCI PERANGKAT LUNAK

## 3.1 Deskripsi Kebutuhan

### 3.1.2 Kebutuhan Non-Fungsional (*Non-Functional Requirements*)

Kebutuhan non-fungsional mendefinisikan batasan kualitas, performa, keamanan, keandalan, dan kebergunaan yang harus dipenuhi oleh sistem aplikasi **Sayur Ikat**. Seluruh kebutuhan dirumuskan secara terukur (*measurable*) dengan parameter kuantitatif dan kriteria uji yang jelas, tanpa menggunakan pernyataan ambigu:

| No. | Kode Kebutuhan | Kategori Kualitas (*Quality Criteria*) | Deskripsi Kebutuhan Kuantitatif | Kriteria Uji / Tolok Ukur Pengukuran (*Metric*) |
| :-: | :---: | :--- | :--- | :--- |
| **1.** | **NFR-PRF-01** | *Performance Efficiency* (Waktu Muat Halaman) | Sistem harus dapat memuat dan menampilkan seluruh komponen visual halaman utama (`/`) dalam waktu maksimal **2,5 detik** pada koneksi internet broadband/4G standar (kecepatan unduh $\ge$ 10 Mbps). | Diuji menggunakan alat ukur *Google Lighthouse* atau *Chrome DevTools Network Tab*, dengan metrik *Largest Contentful Paint* (LCP) $\le$ 2,5 detik. |
| **2.** | **NFR-PRF-02** | *Performance Efficiency* (Respon Waktu API) | Waktu pemrosesan eksekusi penyimpanan transaksi pada endpoint API pesanan (`POST /api/orders`) tidak boleh melebihi **1,0 detik** untuk memvalidasi data dan mengembalikan nomor ID pesanan. | Diuji melalui pengukuran *API Response Time* di lingkungan pengujian normal dengan hasil durasi respons HTTP $\le$ 1000 milidetik. |
| **3.** | **NFR-USB-01** | *Usability* (Tingkat Kebergunaan Antarmuka) | Antarmuka pengguna harus intuitif dan mudah dipahami oleh pengguna baru (konsumen rumah tangga) tanpa memerlukan pelatihan operasional khusus. | Diuji menggunakan kuesioner terstandar *System Usability Scale* (SUS) kepada minimal 10 responden uji dengan perolehan skor rata-rata minimal **75 dari 100** (kategori *Good / Grade B*). |
| **4.** | **NFR-SEC-01** | *Security* (Keamanan Transmisi & Data) | Seluruh transmisi data antara peramban klien dan server harus dienkripsi menggunakan protokol HTTPS (TLS 1.2 / TLS 1.3), serta sistem wajib memvalidasi dan menolak berkas unggahan bukti ulasan yang bukan berupa format citra resmi atau berukuran lebih dari 5 MB. | Validasi sertifikat SSL/TLS aktif pada domain aplikasi (*insecure warning* bernilai nihil), dan pengujian unggahan berkas executable/citra > 5 MB menghasilkan penolakan status HTTP 400. |
| **5.** | **NFR-AVL-01** | *Availability* (Ketersediaan Layanan) | Sistem perangkat lunak dirancang untuk memiliki target ketersediaan layanan (*Service Level Target*) minimal **99% uptime** setiap bulan selama jam operasional pemesanan (06.00 – 22.00 WIB). | Total waktu henti (*downtime*) tak terencana di luar pemeliharaan terjadwal tidak melebihi 7,2 jam dalam rentang waktu satu bulan kalender. |
| **6.** | **NFR-REL-01** | *Reliability* (Integritas Transaksi) | Sistem harus menjamin integritas data pesanan relasional antara tabel pengguna (`users`), pesanan (`orders`), dan rincian item (`order_items`) menggunakan transaksi Prisma ORM, sehingga tidak terjadi inkonsistensi data jika koneksi terputus di tengah proses. | Pengujian simulasi kegagalan jaringan saat *checkout* tidak meninggalkan data pesanan yatim (*orphaned records*) di database. |
| **7.** | **NFR-POR-01** | *Portability & Responsiveness* (Kompatibilitas Layar) | Antarmuka aplikasi web harus responsif dan mempertahankan tata letak proporsional tanpa kerusakan visual atau *horizontal scrolling* pada berbagai ukuran layar dengan lebar *viewport* mulai dari **360 piksel** (layar *smartphone*) hingga **1920 piksel** (layar *desktop*). | Diuji pada peramban Google Chrome, Apple Safari, Mozilla Firefox, dan Microsoft Edge menggunakan mode *Responsive Design Testing* (360px, 768px, 1024px, 1440px) tanpa ada elemen yang terpotong. |
